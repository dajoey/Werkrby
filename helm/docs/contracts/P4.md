# Contract P4 — Producers: Escalation Path, MCP Spark Repoint, Deterministic Sweeps, Planka Ingest

Owner: AGY worker. Issue: helm#7.
Status: spec-first contract (work order step 0). Follows LESSONS.md (3, 10, 13, 15, 21, 27, 33, 39, 40) and PLAN.md.

The one-sentence spec: **Provide a deterministic, zero-LLM escalation path for every unattended job and sweep (stable daily ID, ack-only, log tail, fallback), repoint MCP spark tools at standalone Helm, deliver deterministic sweeps (kuma-down, stack-status, quota-floor), and gate Planka ingest retirement behind an explicit decision thread to Joey.**

## §0 Architecture & Principles (LESSONS 3, 10, 13, 21, 27, 33)

1. **Deterministic Facts, Zero LLM on Critical Path (LESSON 33)**: All health checks, exit code evaluations, log tail slicing, and deduplication logic run in pure Python. No model inference is ever in the decision path for whether a thread is filed.
2. **Stable Daily Thread IDs (LESSON 10)**: Thread IDs follow the pattern `sched-<job-id>-failure-<YYYYMMDD>` and `sweep-<name>-<YYYYMMDD>`. Because Helm store Invariant 2 forbids reopening a `done` thread, the date stamp ensures a resolved failure today does not suppress a recurrence tomorrow, while deduplicating repeated hourly runs on the same calendar day into a single thread.
3. **Ack-Only Asks for Pure FYIs (LESSONS 13, 15)**: Scheduled job failure escalations present `ask_kind="ack"` ("A scheduled job failed. Acknowledge once you've looked."). An ack carries nothing to decide; tapping "Got it" settles the thread immediately without bot dispatch.
4. **Dry-Run Purity (LESSON 21)**: Running any producer or sweep with `--dry-run` performs data retrieval and evaluation but executes ZERO side effects: no HTTP calls to Helm, no disk mutations, no heartbeat timestamp changes.
5. **Heartbeat on Every Run (LESSON 21)**: Every sweep and unattended runner writes or updates a local heartbeat file (`.heartbeat`) on every execution, including clean runs where no alert was needed.
6. **Hysteresis & Anti-Flap**: Transient network blips must not wake anyone. Monitors use streak thresholds (e.g. >= 3 consecutive failed checks for Kuma) before escalating.

## §1 Escalation Path for Unattended Jobs (`file_helm_thread.py`)

1. **Module & Tooling**:
   - Repository source: `tools/file_helm_thread.py`
   - Fleet deployment: copied into the operator's ops directory (`$HELM_OPS_DIR`)
2. **CLI Signature**:
   ```bash
   file_helm_thread.py <job-name> <exit-code> <log-path> [--dry-run]
   ```
3. **Pure Builder (`build_thread`)**:
   - Accepts `(job, exit_code, log_path, links=None, esc_note="", now=None)`.
   - Normalizes `job` name into a lowercase dash-separated slug.
   - Extracts the last 40 lines of `<log-path>` defensively (UTF-8 with replacement, graceful fallback if missing).
   - Exit code != 0:
     - `thread_id`: `sched-<job-slug>-failure-<YYYYMMDD>`
     - `title`: `[<job>] run failed (exit <exit-code>)`
     - `category`: `Scheduled Jobs`
     - `urgency`: `this-week`
     - `ask`: `{"kind": "ack", "prompt": "A scheduled job failed. Acknowledge once you've looked."}`
     - `events`: includes one event of kind `log-tail` containing the last 40 lines.
   - Exit code == 0:
     - `thread_id`: `sched-<job-slug>-review-<YYYYMMDD>`
     - `title`: `[<job>] review requested`
     - `urgency`: `whenever`
     - `ask`: `{"kind": "ack", "prompt": "A scheduled job finished and flagged something worth a look."}`
4. **Transport & Fallback**:
   - Primary: HTTP `PUT /api/triage/threads` to standalone Helm using credentials from the environment, or from the dispatch env file named by `HELM_DISPATCH_ENV` (`HELM_URL`, `HELM_APP_TOKEN`).
   - Fallback: If Helm is unreachable or returns non-200, emit loud `[HELM-FALLBACK]` diagnostics to stderr (job, exit code, log path) so the failure is still visible to whoever reads the job log.
   - The escalation helper never masks or alters the exit code of the monitored process.
5. **Cron Integration**:
   - High-impact unattended jobs wire failure escalation via `|| file_helm_thread.py <job> $? <log>`.

## §2 Repoint MCP Spark Tools (`file_issue`, `helm_threads`, `board_pulse`)

1. **`file_issue`**:
   - `needs_joey` parameter is strictly REQUIRED (minimum 15 characters).
   - Generates stable thread IDs using `issue-<slug>`.
   - Checks existing threads via `GET /api/triage/threads?include_done=1` to enforce 14-day suppression on recently settled issues.
   - In dry-run mode (`dry_run=True`), returns `{"ok": True, "action": "dry_run", ...}` without writing.
   - Shapes choice ask (when `options` given with >= 2 options) or ack ask.
   - Delivers to Helm via `PUT /api/triage/threads` using `HELM_URL` and `HELM_APP_TOKEN`.
2. **`helm_threads`**:
   - Fetches live thread records directly from `GET /api/triage/threads` with state filtering.
3. **`board_pulse`**:
   - Gathers live facts: open Helm thread counts grouped by state (`needs-you`, `working`, `waiting-external`), cron failure streaks, gateway service status, and disk metrics.
   - Pure facts, zero judgment.

## §3 Deterministic Sweeps (`producers/sweeps/`)

Sweeps follow the clean 4-step pipeline: **`fetch -> shape -> decide-as-data -> apply`**.

1. **`kuma_down` (`producers/sweeps/kuma_down.py`)**:
   - `fetch`: HTTP GET the Uptime Kuma URL (`KUMA_URL`, or `--url`) with a 10s timeout.
   - `shape`: `{kuma_up: bool, http_code: int, timestamp: float}`.
   - `decide`: Compares failure count against `ALERT_AFTER = 3` threshold.
   - `apply`:
     - If down >= 3 runs: upserts `sweep-kuma-down-<YYYYMMDD>` in Helm with `category="Fleet health"`, `urgency="immediate"`, and multiple-choice options to restart or inspect.
     - If recovered: settles thread or logs clean recovery.
     - Writes heartbeat to `.kuma-down.heartbeat`.
2. **`stack_status` (`producers/sweeps/stack_status.py`)**:
   - `fetch`: Concurrently probes the configured core service endpoints (`HELM_CORE_SERVICES`, a JSON list of `[name, url, [valid_codes]]`; a built-in fallback list is used when it is unset).
   - `shape`: `{healthy: bool, failed_services: [str], results: {svc: code}}`.
   - `decide`: If core services are unreachable, decides to raise `sweep-stack-status-<YYYYMMDD>`.
   - `apply`:
     - Upserts Helm thread with failed service names, logs, and ack/remediation options.
     - Settles thread when all services return to healthy.
     - Writes heartbeat to `.stack-status.heartbeat`.
3. **`quota_floor` (`producers/sweeps/quota_floor.py`)**:
   - `fetch`: Reads SQLite token ledgers (`state.db`), recent worker fallback logs, and profile model chain configs.
   - `shape`: `{paid_tokens: int, fallback_lines: int, dirty_chains: int}`.
   - `decide`: If paid burn detected (T1 usage, T2 fallback lines, T3 dirty chains), triggers brake and thread.
   - `apply`: Upserts `t-quota-floor-guard` thread in Helm; auto-releases brake and settles thread when condition clears.
   - Writes heartbeat to `.quota-floor-guard.heartbeat`.

All sweeps support `--dry-run`, `--selftest`, and `--heartbeat`.

## §4 Legacy Ingress Retirement

A legacy ingress is retired only on an explicit owner decision delivered as a
`needs-you` thread, never on a worker's own judgement. Until that thread is
answered the old ingress stays installed and running, so nothing is lost if the
answer is "keep it". The thread states, in the owner's terms, that every
producer now files directly to Helm and that the legacy poller is therefore
redundant, and offers `retire` and `keep` as named options.
