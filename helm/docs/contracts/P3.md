# Contract P3 — Dispatcher v2 (executor-agnostic pump)

in-session). Issue #4. Depends: P2 code (merged), P2b spike findings (merged).

## What this delivers

`dispatcher/` — the pump, per work-Helm §5 + our lessons. NO model inside the pump;
it claims, spawns an executor adapter, records. Executors: `claude -p --bare` (reference
adapter) and `hermes -z` (second), both behind the adapter interface from
SPIKE-P2b §7 (from_<runtime>() readers, one Result shape).

1. **Tick algorithm** (systemd timer, 1-min, flock single-instance on main shell fd):
   heartbeat every run incl. no-ops → spending brake → claim (via POST /claims BEFORE
   spawn) → spawn adapter w/ caps → result posted exactly once (by the harness) →
   attempts recorded; backoff; 5 attempts → gave_up (visible) + restore-to-ack path.
2. **Jail outside the CLI** (spike finding): executors run under `systemd-run --scope`
   with `ProtectSystem=strict`, `ReadWritePaths=<run_dir>`, `PrivateTmp=true`, a
   dedicated `helm-exec` UID (no login, no sudo), and no network except the gateway
   (the harness posts results; the executor gets NO network tool). Escape test from
   the spike (write outside run dir) must be re-fired IN the jail and refused; if any
   write lands outside, P3 does not ship.
3. **Caps**: wall clock (timeout(1)), budget (--max-budget-usd on claude; token-count
   brake on hermes since dollars are unreportable — cost_basis never summed as 0),
   turns (observed + wall-clock proxy), rounds per thread (4; snoozes/store events
   excluded — count only run-produced events). Fire one cap ON PURPOSE in tests so
   capped/timed_out are fired guards, not code.
4. **Spending brake**: reads hermes-usage-exporter artifacts; stale/unreadable = HOLD
   with reason word "usage-blind" ≠ "usage-over" (distinct words, fail closed).
5. **Boundaries as code**: tier lists + allowlist AND denylist per runtime; the prompt
   renders the switches AS THEY ARE on this run (never describe a tool that is denied).
6. **Watchdog on a second host** (deliberately not the dispatcher's): heartbeat-file age +
   pending-dispatch age + claims-expired-without-result; pages via Helm thread only.
7. **Retention**: run dirs 30d (the work version hit 1.3 GB in 10 days).
8. **--selftest + --dry**: dry writes NOTHING (verified by probe); selftest covers
   brake-reasons, adapter parse of a recorded run, jail refusal.

## Gates (close criteria)

- [ ] One REAL answered thread executed E2E with run-dir evidence (prompt, result.json,
      usage) and the thread settling correctly per store gates.
- [ ] kill -9 mid-run: claim expires → thread re-offered (at-least-once), no duplicate
      live claims.
- [ ] Escape test refused inside the jail, evidence captured.
- [ ] Cap fired on purpose once (wall clock + budget), partial result kept.
- [ ] Brake: stale meter file → hold with "usage-blind", distinct from over-budget.
- [ ] Heartbeat touched on a no-op tick.

## open-questions (added by the P3 worker, 2026-09-12, with measured evidence)

Deviations and unknowns encountered while building dispatcher/ — each chosen
conservatively, each recorded here rather than improvised silently (task rule:
"ambiguity → write it into §open-questions and choose conservatively").

1. **`systemd-run --scope` cannot sandbox** — user mode AND root reject
   `ProtectSystem=strict` with "Unknown assignment" (measured on systemd 255).
   The jail therefore uses a transient **service**
   (`systemd-run --collect --wait --unit=...`) with the exact property set the
   contract names (ProtectSystem=strict, ReadWritePaths, PrivateTmp) plus
   ProtectHome=read-only (below). Same security semantics as an intended
   --scope; only the unit kind differs. Tests prove enforcement live.
2. **ProtectSystem=strict alone does NOT protect /home on this host** — a
   jailed write to `$HOME/.jesc-A-*` LANDED (measured; /home is on the root
   fs, not a separate mount). `ProtectHome=read-only` is added to the jail and
   the escape test re-fires the home write and requires refusal. Contract
   named ProtectSystem only; the measured gap is closed and documented.
3. **`IPAddressDeny=private` does not parse on systemd 255** — "Failed to
   parse IP address prefix". `IPAddressDeny=any` is used instead (measured:
   loopback curl inside the jail fails, rc 28). Executors get zero network,
   which is also what the contract demands ("no network except the gateway"
   is moot since the harness, not the executor, posts results).
4. **helm-exec UID does not exist yet** on the dispatcher host. Jail falls back to the
   invoking uid with all namespace protections intact; tests run under the
   invoking uid deliberately (HELM_JAIL_EXEC_UID). Creating the user is an
   ops action for the E2E pass (needs root, out of this worktree's scope).
5. **RuntimeMaxSec kill leaves rc 1, not 124** (measured) — so the wall-clock
   cap is `timeout(1)` INSIDE the jailed wrapper: rc 124 has one meaning on
   every mode, matching the spike, and the service cannot outlive its cap
   (an outer timeout would kill only the systemd-run client).
6. **Claims release**: a failed run must not block re-claim until lease
   expiry — P2 defined released_at but no route sets it. Added
   `POST .../claims/{claim_id}/release` (service.py, claims table unchanged;
   not a store.py gate change). The tick releases on every no-result exit.
7. **Round-cap hand-back is itself a bot-result event** — counting it as a
   round made a capped thread permanently stuck at round 5. bot_rounds()
   now excludes source_id `dispatcher-roundcap` (same class as the work
   system's wake-events-counted-as-rounds bug). Tested: a fresh reply after
   hand-back still dispatches.
8. **Watchdog heartbeat transport**: the watchdog host cannot read the
   dispatcher host's disk; the tick publishes its heartbeat to the gateway
   (POST /api/triage/dispatcher-heartbeat, file-backed, no store change) and
   the watchdog reads it via GET. Separate failure domains preserved: if the
   dispatcher host dies, the heartbeat goes stale and THAT is the alert.
9. **Brake data source**: hermes-usage-exporter's real outputs on this host
   are (a) a VictoriaMetrics series hermes_tokens_total (cumulative
   counters, 10-min pushes) and (b) its log file mtime. The brake queries VM
   for windowed increase() + newest-sample freshness; VM unreachable falls
   back to log mtime; both unreadable → usage-blind. Threshold defaults to
   400M tokens/24h fleet-wide, env-tunable; calibrating it to Joey's actual
   ceiling is left to live tuning (P4b audit data exists for it).
10. **PENDING for the live E2E (orchestrator's gate, not this pass)**: kill -9
    of a REAL run with claim expiry timing (offline test covers the mechanism
    via DB time-travel), the real claude budget-cap subtype string
    (`success_budget` is the stub's guess — the spike never hit the cap, so
    the real string is unmeasured), and a real answered thread executed E2E
    with run-dir evidence. Also: `claude auth status` JSON shape is stubbed;
    the real CLI's field names (`loggedIn`/`authMethod`) are inherited from
    the work reference, not re-measured on this claude 2.1.246 install.
