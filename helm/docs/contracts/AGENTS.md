# Phase Contracts DOX

## Purpose

- Own the per-phase specifications of the helm subsystem: P1 store kernel, P2 standalone service, P2b executor-runtime spike, P3 dispatcher, P3b self-resolution ladder, P3c learning loop, P4 producers and sweeps, P6 label-driven intake routing, P7 dispatcher resilience.
- Each file fixes one phase's scope, dependencies, rules with their lesson citations, acceptance gates, and a `§open-questions` section that answers every ambiguity conservatively and flags it.
- These are the documents a commit points at when it changes a gate, and the text the shipped behaviour was graded against.

## Local Contracts

- A contract is written and committed BEFORE its code, so the result cannot be graded against a moving target. It is never rewritten afterwards to match what shipped: deviations, measured gaps and refusals are appended to `§open-questions` with the evidence that produced them (P3 lists ten, P7 five).
- Every rule cites the `LESSONS.md` number or `PLAN.md` rule it implements. A rule with neither does not belong in a contract file, and a lesson that governs the phase but is missing from its contract is a bug in that contract.
- Filenames are phase ids and the sequence is deliberately not contiguous: P5 and P5b were deployment-side and never landed here. Do not renumber to close the gap and do not reuse a retired id.
- Layer boundaries are the spine of the design and every contract restates them. The store (P1 §6) is pure: no HTTP, no model call, no subprocess, no filesystem writes beyond its SQLite file. HTTP is P2's service layer, spawning and jails are P3's dispatcher, and the correction classifier is a separate package that imports nothing from the store (P3c §0). A `GATE:` shell command is data the store stores and hands out through an injected callable; the store never executes it.
- Every rejection is a 400 whose detail is specific enough for the producer that sent the payload to fix itself on retry, and `put_threads` keeps partial success: a bad thread is named in `rejected[]` while the rest of the payload lands.
- Park invariants (P1 §1): `waiting-external` requires a `blocked_on` of at least 8 characters that does not name the owner; `recheck_at` defaults to six hours out, is coerced up when already past, and 400s beyond 30 days; a park that reaches 30 days expires into a real choice ask. Any other state clears the park fields on write. Snoozes are exempt — `wake_at` plus the in-store wake sweeper is their machine-checkable exit.
- Answer gate (P1 §2): when the newest unconsumed owner note is newer than the newest bot result and contains `?`, the result must carry `answers` of at least 12 characters, rendered first in the history event. Detection is a literal `?` test, never a model, and P7 §2 refuses to exempt it even for a deliberate no-action verdict.
- Exactly three mechanical bot-closes exist and nothing else closes a thread without the owner: ack-tapped, answered-decision with `answer_applied` and `nothing_owed` both asserted as literal booleans, and P7's `no_action: true` (valid only with `state: "done"`, only when a reply is newer than the current ask, reported as `closed_by: "no-action-settle"`). Completion is never inferred from prose, and a `done` post carrying a fresh choice or text ask stays refused.
- Self-contained asks (P1 §3): choice labels are rejected for external references, deictic-only, index-only and list-token forms, and for duplicate labels in one ask. `ask.context` is the single escape hatch, licenses only the tokens it actually defines, is capped, is held to the same external-reference standard as the labels, and is cleared wherever the ask is cleared.
- Escalation gate (P3b §1): the four-test decision function is pure deterministic code running T1..T4 in order and returning the first failure. T1 evidence is `ask.requires` drawn from `{decision, money, credential, presence, contact}` — absent markers fail T1, an unknown marker is a 400, and ack asks are exempt at the producer's door. Markers are door evidence, checked and dropped, never row state.
- Bare cards never light an optionless demand (P3b §4): the phrase "what do you want" is banned in any stored ask at either door; a needs-you text ask with no options and no `?` is a 400; a pure direction-demand is deterministically rewritten into an ack-style summary flagged `rewritten_ask: true`.
- Rounds count only events a run produced: snoozes, store-generated events, skeptic hand-backs and round-cap hand-backs are excluded, or a capped thread strands at the cap forever. The second-lane review grants one bonus round, once ever, and the prefix it writes into the event log IS that marker — no new column, no dispatcher-local state.
- Learning loop (P3c): classification is deterministic and never adopts; adoption is the owner's tap, and the store files its own lesson thread through the ordinary producer door so it passes the gates producers face. Retired lessons never render into a prompt, the render read is capped and fails open with a loud log line, and a `GATE:` lesson stays visibly pending until its implementing commit is recorded.
- Producers (P4) and intake (P6): thread ids carry a date stamp (`sched-<slug>-failure-<YYYYMMDD>`, `sweep-<name>-<YYYYMMDD>`) so a failure settled today cannot suppress tomorrow's recurrence; `--dry-run` performs zero side effects; a heartbeat is written on every run including clean ones; hysteresis thresholds precede any page; label prompt templates are data in the `labels` table, tunable without a code change; and a legacy ingress is retired only on an explicit owner decision thread, never on a worker's judgement.
- Service compatibility (P2): route paths, methods and 2xx/400/404 shapes are a compatibility target for clients already in the field, and live detail strings producers parse are carried over verbatim except where a store rejection already covers them — the store's message wins on overlap. Claims are the executor-agnostic surface: claim before spawn, one result posted through `post_result` so every gate applies, expiry visible with its own reason word.
- Jail and credentials (P3 §2, P7 §1): executors run in a transient systemd service with `ProtectSystem=strict`, `ProtectHome=read-only`, `ReadWritePaths` limited to the run directory, `PrivateTmp`, and `IPAddressDeny=any`; the wall clock is `timeout(1)` INSIDE the jail so rc 124 means one thing on every path. `HELM_PROVIDER_ENV_VARS` is additive and may never replace the set in a way that drops a fallback runtime's credentials, and the bearer variable the reference CLI actually reads is `ANTHROPIC_AUTH_TOKEN`.
- Acceptance is evidence, not prose: suites are discovered rather than listed, so a new gate's suite cannot be quietly forgotten; every new refusal must be fired by a probe that returns 400; and the "as landed" suite and check counts each contract records are historical stamps tied to their commit, not live numbers to keep editing.
