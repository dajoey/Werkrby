# Helm Store DOX

## Purpose

- Own `store.py`, the durable kernel of the Helm triage board: threads, append-only events, asks and answers, snoozes, parks, attachment metadata, mute suppressions, the lesson ledger, labels and settings.
- Own the one SQLite file all of that lives in. Its path comes from the `HELM_DB` environment variable, falling back to `data/triage.db` beside this package; `db()` opens it with WAL, `foreign_keys=ON`, and runs `init()` on every open.
- Stay pure store logic: no HTTP, no model call, no subprocess, no file bytes. Everything here is deterministic and testable offline against a throwaway database, so a wrong card can be blamed on the store or on its caller, never on both.
- Own the rejection prose. Validation is hand-written, not schema-driven, because the reader of a 400 is usually the model that produced the payload and has to fix itself without a second round trip.

## Local Contracts

- The five invariants in the module docstring are the product, and nothing here may weaken them: (1) `put_threads` is an upsert that retires only ids named in `tombstones`; (2) a `done` thread is never dragged back by a producer PUT; (3) an answer in flight (`_answer_is_in_flight`) freezes state, ask kind/prompt/options/context and `links` against resync; (4) a `needs-you` thread always carries an ask — `needs-you` with `ask.kind == 'none'` is refused at the producer door and at `post_result`; (5) tapping `ack` on an `ack` ask settles it in `reply()` instead of dispatching a run.
- Closed vocabularies are validated, never coerced: `VALID_STATE`, `VALID_ASK`, `URGENCY_ORDER`, `VALID_INTENT`, `REQUIRES_MARKERS`, `VALID_LABEL_RUNTIMES`. A value outside the set is an error, because a silently rewritten one is a lie the store then serves forever.
- Only the owner closes a thread. `close_thread` refuses any `actor` but the owner token (the value of `HAND_ID_PREFIX` without its trailing dash), and `bot_close_reason` grants exactly three mechanical exceptions to `post_result`: `ack-tapped`, `answered-decision` (requires literal `answer_applied` **and** `nothing_owed`), and `no-action-settle` (requires a reply newer than the current ask). Anything else is a 400; a run that believes it is finished lights an `ack` ask in the same post and the close is the owner's tap. Those assertions are data, never prose: `_bool_flag` rejects `"true"`, `1` and every non-boolean, `reply()` clears both columns, and a new `choice`/`text` ask or a handed-back close clears them again.
- History is append-only and content-addressed: `event_id` is a 32-hex truncation of `sha256(thread_id|ts|source|kind|body)` and `add_event` is `INSERT OR IGNORE`, so re-running a pass is idempotent rather than additive. `source_id` is deliberately outside the hash, so a dedupe key alone does not make an otherwise-identical event distinct. Owner-authored kinds are `<owner>-reply`, `<owner>-note`, `<owner>-attachment`; runs write `bot-result` and `bot-ask` under source `bot`; `bot-ask` exists because `ask_prompt` is mutable and "did he reply after the ask" has to stay answerable a generation later (`newest_ask_ts`, `_generation_start`).
- `post_result` enforces the note floor and the answer gate: `note` is required, `MIN_RESULT_NOTE`..`MAX_NOTE` chars, and is the only thing rendered into history — `outcome` is a status word. If `unanswered_questions()` finds any `?`-shaped fragment in owner notes written since the last `bot-result`, the result must carry `answers` of at least `MIN_ANSWER` chars, rendered above the report. `links` is cleared only by an explicit empty list; an absent key leaves the stored value alone (`COALESCE` on a SQL `NULL`).
- `waiting-external` is a claim with an owner and an expiry, not a hole. `park_fields` requires `blocked_on` of at least `MIN_BLOCKED_ON` chars that does not match `_WAITS_ON_OWNER`; `recheck_at` defaults to `DEFAULT_RECHECK_S` and is capped at `MAX_RECHECK_S`; the optional `gate_cmd` is one line under `MAX_GATE_CMD`. `parked_since` is preserved across resyncs and parks so nothing can reset the 30-day expiry clock, after which `apply_recheck` turns the park into a real choice ask.
- The park's exit runs outside the store: `due_rechecks` hands the gate command out as data, `sweep_rechecks` takes an injected `run_gate` callable, and a runner that raises is recorded as still-blocked — a broken checker must never buy silence. `adopt_legacy_parks` staggers pre-contract parks minutes apart instead of dumping them into one pass.
- `wake_at` is an epoch float and `0` means not snoozed. A snoozed thread is hidden from `list_threads` and stashes its live ask in `wake_ask` JSON so hidden and lit are mutually exclusive; `wake_due()` runs *inside* `list_threads`, so a read wakes threads and writes rows. A live deferral survives a bot result (invariant 5): the event still lands, the card stays hidden, and the newest question rides in `wake_ask`.
- The dispatch queue keys idempotency to the reply, not the thread: pending means the newest `<owner>-reply` is newer than `dispatched_at`. `dispatched_at` only ever moves forward (`MAX(COALESCE(...), ?)`) because `post_result` and `mark_dispatched` race. `mode="start"` claims the attempt before the executor is spawned and the failure branch must not charge a second one; at `MAX_DISPATCH_ATTEMPTS` the thread stops being offered and `restore_gave_up` puts it back in front of the owner with its original ask.
- A file is an instruction. `unconsumed_attachments` is measured against the newest `bot-result`; a reply carrying one never settles (the settle is suppressed out loud, in the return and in history), and `close_thread`/`mute` refuse unless `force=True`. The store keeps metadata only — `(thread_id, sha256)` is unique, size and 64-hex digest are validated, and the bytes are the API's business.
- The needs-you four-test (T1 only-he-can, T2 still-true-now, T3 he-doesn't-know, T4 agent-cannot-fix; the first failure is the one returned) fires at the producer door only for a *new* ask reaching the board — a fresh lit thread, or one whose stored ask was `none`. T1 evidence is explicit `ask.requires` markers from `REQUIRES_MARKERS`; those markers are door evidence and are never persisted on the row. A resync of a thread that already carries an ask is licensed and is not re-interrogated.
- The self-contained gate (`self_contained_errors`) and the bare-ask rules (`bare_ask_errors`, `pure_direction_demand`) are deterministic regex only and must stay that way — no model may decide whether a button is legible. `ask.context` is the single escape hatch: a lettered label is legal exactly for the tokens `context_tokens` finds defined on the same card. At the bot door a pure direction-demand is rewritten to `rewrite_to_ack_summary` rather than rejected, and the rewrite is reported as `rewritten_ask`.
- `put_threads` validates every thread before writing anything and succeeds partially: one bad thread costs only itself and is returned in `rejected` with its errors. `accepted` counts rows actually stored (`created + updated + suppressed_on_arrival`), never gate rejections. `thread_id` is required and must be stable across passes; hand-written cards instead mint ids through `_mint_hand_id` (`HAND_ID_PREFIX` + date + slug), skip mute rules, and let `intent` set state and ask together.
- Mute fingerprints are computed from `normalize_subject` — producer prefix, numbers, units, punctuation and stopwords stripped — never from the raw title, because titles carry live measurements. `(producer, fingerprint)` is unique in `suppressions`, and the `categories` table is write-only bookkeeping: `categories_of` recomputes groupings from the live set at read time.
- Lessons are adopted only by the owner's tap. `open_lesson_thread` files through `put_threads` so every producer-door gate fires on the store's own filing; `create_lesson_from_thread` demands an `adopt`/`adopt-with-edit` reply newer than the ask, and `adopt-with-edit` demands the binding note. `supersede_lesson` lands the new row and retires the old in one commit, `retire_lesson` refuses a second retirement rather than no-opping, a `GATE:` rule sets `gate_status='pending'` until `mark_gate_implemented`, and `lessons_for_prompt` renders active `global` + exact scope in `(created_ts, id)` order capped at `MAX_RENDER_LESSONS`.
- Schema changes are additive only: add the column to `_MIGRATIONS` (the `ALTER TABLE` loop in `init`) as well as the DDL, or existing databases never get it. `init` also seeds default labels and settings on an empty table. `claims` is the exception — `init_claims` is a separate call and `db()` does not create that table.
- `StoreError(status, detail, extra)` is the only rejection type; the HTTP mapping belongs to the API layer, which is why the status rides on the exception. `park_fields`/`validate_thread`/`normalize_*` return error lists (for partial success) while the bot-facing doors raise the first one.
