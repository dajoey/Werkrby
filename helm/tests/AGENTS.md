# Helm Tests DOX

## Purpose

- `run_all.py` is the gate: it discovers the suites, runs each as its own process, sums their counts and returns one exit code.
- Seventeen suites live here — sixteen `test_*.py` files plus the adversarial `probe_400s.py`, which always runs last.
- `stub_executor.py` is the only executor these tests ever spawn: a deterministic fake that succeeds, fails, caps out, times out, hangs, tries to escape the jail, or plays the reviewer on demand.
- Everything is offline: throwaway SQLite databases, an in-process gateway on loopback, a fake metrics server, no model call, no billing, no network beyond loopback.

## Local Contracts

- Suites are discovered, never listed. `run_all.py` takes every `test_*.py` in this directory in sorted order and appends `probe_400s.py` last. A new gate lands by being named `test_*.py`; do not replace discovery with a hand-kept list, and do not move the probe out of the run — it is the only evidence the gates are wired rather than merely written, so it is part of "green".
- The count line is the protocol between a suite and the runner: the **last** line matching `^(\d+) passed, (\d+) failed` at column zero is that suite's total. A suite must print it *and* exit nonzero when anything failed. A nonzero exit with no counts is forced to one failure, so a suite that dies on import is reported as a failure instead of as zero-of-zero.
- These are plain scripts, not pytest. Each suite owns its own `check(name, cond, detail)` counter and its own `SystemExit`; there is no `__init__.py`, no conftest and no shared fixture module. The runner sets the working directory to the subsystem root and each suite inserts that root on `sys.path` before importing `helm.store`, `app.service` or `dispatcher`.
- Set environment before import. `app/service.py` reads `HELM_APP_TOKEN`, `HELM_DB` and `HELM_ATTACH_DIR` into module constants at import time, so every suite forces the token to a test value and points the database and attachment directory at a `tempfile.mkdtemp` tree *above* the import line. Hoisting the import runs the suite against the real configuration.
- Four suites bind a real uvicorn gateway on a fixed loopback port — two on 3039, two on 3041 — so suites must run one at a time, exactly as the runner does. Never parallelize the run, and give a new gateway suite one of the existing ports rather than a third listener.
- Run directories go under `$HOME`, never `/tmp`: jail service mode gives the spawned unit its own private `/tmp`, so a `/tmp` run directory is invisible inside the jail (measured — a control write appeared to fail until it moved). Each such suite removes its `$HOME/.helm-*-test-runs` tree at startup to stay hermetic across reruns, and pins the jail's exec uid and gid to its own.
- `HELM_CLAUDE_BIN` and `HELM_HERMES_BIN` must both point at `stub_executor.py` before `dispatcher` is imported. Missing either one makes the suite invoke a real, billed CLI.
- The stub's behaviour is `HELM_STUB_MODE`: `ok`, `ok-notext`, `fail`, `auth-fail`, `cap-budget`, `cap-turns`, `timeout`, `escape`, `slow-escape`, `hang-after`, `note-only`/`note-only-malformed`, and one reviewer mode per verdict plus `review-invalid`, `review-garbage` and `review-empty`. It writes only inside `HELM_RUN_DIR`, and an `auth status` invocation is answered like the real CLI *before* mode dispatch — the dispatcher calls it outside the jail, and the escape mode once fired from that unjailed precheck. Runtime shape decides the override: `-z` in argv means the hermes-shaped spawn, where `HELM_STUB_MODE_HERMES` wins — that is how one tick has one runtime fail its last attempt while the switched runtime succeeds. A prompt carrying the round-cap bonus marker downgrades a review mode back to `ok`, because that run is an executor run and must write `result.json`, never the reviewer artifact.
- The reviewer artifact is `review-result.json` = `{verdict, note}` with the verdict one of the three in `VERDICTS` (ready, one-more-round, escalate-to-the-owner) and the note over the 80-character floor (`MIN_REVIEW_NOTE` in `dispatcher/skeptic.py`). Shorten the stub's note and admissible verdicts start reading as invalid.
- Escape is proven by absence: the escape modes try to write `~/.helm-p3-escape-sentinel` and `/tmp/helm-p3-escape-sentinel`, and the assertion is that neither exists after a jailed run. `slow-escape` also writes a valid `result.json` so the run *looks* fine, precisely so the assertion can hinge only on the outside files.
- The four suites that drive `dispatcher/tick.py` as a subprocess (`test_dispatcher`, `test_ladder`, `test_learning`, `test_p7_resilience`) spawn through the real jail. Service mode requires systemd as PID 1, `systemd-run` and passwordless sudo; anything else is `fallback-degraded`, which refuses untrusted spawns unless explicitly opted into. Failures there are an environment limit, not a regression.
- Every thread a store-level suite or the probe creates needs a distinct title: `mute()` suppresses by title fingerprint and the fingerprint strips digits and single-letter stopwords, so one shared default title makes every later card a duplicate and auto-retires it. Newly lit `choice`/`text` asks also need their `requires` marker, or the producer-door gates fire before the rejection under test.
- `probe_400s.py` scores a refusal only when it is a `StoreError` with status 400 — 404 solely for an unknown thread id, or a named entry in `rejected[]` while the rest of the payload still lands — **and** the thread is left in the state it was in before. A guard that refuses and mutates anyway is not a guard. Keep the positive controls beside each probe: a suite that only ever refuses proves nothing.
- Store-kernel suites run with no HTTP at all and guard: `test_store` every invariant that shipped broken at least once; `test_park` that a parked state always carries a machine-checkable exit; `test_snooze` durations, validation, ask preservation, list hiding and the owner's own reply clearing the snooze; `test_answer_gate` that a question in a binding note is answered before anything else; `test_self_contained` that an option survives being screenshotted alone; `test_attachments` that a file plus a tap never settles the card and no blob column exists; `test_bot_close` that only the owner closes, with the two exceptions being his own taps.
- Route-level suites guard: `test_api` every route through raw ASGI; `test_append_note` that the note route appends exactly one event plus the mirror, in any state, without re-arming dispatch; `test_email_digest` push/read plus file persistence across a simulated restart; `test_p6_labels` label and settings schema, CRUD, exact UI copy and the dispatcher's label prompt template; `test_p4_producers` the pure build/shape/decide/apply split of the producers and sweeps, including dry-run purity.
- Dispatcher-level suites guard: `test_dispatcher` claim-before-spawn ordering, result-posted-exactly-once, backoff to a visible `gave_up` and the restore path, caps, brake words, retention, single-instance locking, crash recovery, `--dry` and `--selftest`; `test_ladder` the four-test with its positive controls, the retry that switches runtime on the last attempt, the round-cap review verdicts and the banned-phrase sweep over every stored ask; `test_learning` the deterministic classifier, lesson-thread lifecycle, ledger, prompt render and pending gates; `test_p7_resilience` the note-only settle, provider credential names surviving into the jail's environment file, a switch with no usable auth refused before a claim is burned, and the regression that genuine failure still reaches `gave_up` and restore.
