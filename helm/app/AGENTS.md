# Helm Service DOX

## Purpose

- Own the Starlette ASGI application in `service.py`: the route table, the bearer-auth and telemetry middleware, and the module-level `app` object a server imports and runs.
- Own the HTTP edge only. Triage meaning — threads, asks, results, lessons, settings, labels — belongs to the store module; this directory parses requests, makes one store call, and serializes the answer.
- Own the HTTP-side state that deliberately never enters the store: in-process Prometheus counters, the pushed email-digest file, and the dispatcher heartbeat file.
- Own the read-only `/settings` HTML view of current intake settings and configured labels.

## Local Contracts

- Handler shape is fixed: parse, one store call, JSON out. `_db()` opens a fresh SQLite connection per request, sets `PRAGMA foreign_keys=ON`, runs `store.init_claims`, and every handler closes it in `finally`. No connection is cached at module level or shared across requests.
- `store.StoreError` is the only sanctioned rejection path. `_rej` answers with the exception's own `status`, `{"detail": exc.detail}` merged with `exc.extra`. Never invent a status code for a store refusal, and never catch a `StoreError` to soften it.
- Status codes are a compatibility contract with the existing app and web clients: reads 200, `create_thread` 201 and `attach` 201, every mutation 202, the producer `PUT /api/triage/threads` 200 except that an all-rejected batch (`accepted == 0` with `rejected_count > 0`) returns the same body at 400.
- Auth fails closed and is header-only. `TOKEN` is read from `HELM_APP_TOKEN` once at import; when it is empty every non-open path answers 500 "refusing open" rather than serving. `OPEN_PATHS` is an exact-match set of the two unauthenticated paths, `/api/meta` and `/metrics`; nothing opens by prefix, so a later route whose path merely starts `/api/meta` stays authenticated, as do health and status. `_authorized` compares the whole `Authorization: Bearer <token>` header with `hmac.compare_digest` over UTF-8 bytes, and a malformed or non-encodable header is unauthorized rather than an exception. There is no `?token=` query fallback: a token in a URL is copied verbatim into access logs, proxy logs and browser history.
- Middleware order is load-bearing. Telemetry wraps auth, so 401s and 500s are still counted and still carry `X-Trace-ID` and `X-Response-Time`. An unhandled exception becomes a 500 JSON body carrying the trace id, and is best-effort written through `store.record_operational_error` under component `gateway`; that write swallows its own failures so the error path can never mask the original error.
- Metric label cardinality is bounded by the route table, not by the request. `build_app` compiles every registered route path into a matcher, path parameters collapse to `/:id` (the label the old id regex already produced for `t-` thread ids, so existing series did not churn), and every path matching no route is counted under the single `UNMATCHED_PATH` key; an unrecognized HTTP method collapses to `OTHER`. Telemetry wraps auth, so 404s, scanner probes and rejected 401s are all counted, and none of them can add a series to `/metrics`. A new route is picked up automatically — there is no id regex left to extend.
- Claims are the one surface where this directory writes SQL directly, against the `claims` table the store's DDL creates. Keep the invariants here: a claim is live while `released_at IS NULL AND result_at IS NULL AND deadline > now`; a create against a live claim is 409 with the holder's `claim_id`; an expired claim is auto-released and superseded; `result_at` is terminal, so re-report and late release are 409; release is otherwise idempotent so a crashed run can re-claim on the next tick instead of colliding with its own dead lease. Lease length comes from `HELM_CLAIM_LEASE_S` in seconds.
- `claim_result` must keep routing through `store.post_result` so every store gate applies. Executor accounting (`executor_id`, `runtime`, model, cost and basis, duration, turns, capped, timed out, permission denials, `claim_expired`) rides in as the result body's `executor` field and is snapshotted again into `claims.reported`.
- Attachment integrity is computed server-side: `size` and `sha256` are always recomputed from the decoded bytes, so client-supplied values are ignored. `store.normalize_attachment` errors are 400. The store record is written before the file at `<HELM_ATTACH_DIR>/<thread_id>/<att_id>.bin`, so a failed write leaves metadata without bytes; a read requires both the file and a matching metadata row, else 404. Both ids are re-checked against `store.IDENT_RE` by `_safe_segment` at the join site, not only where the row was created: they arrive here from the URL, Starlette's default converter matches `..`, and `attachment_get` stats the path before it asks the store anything, so a store-side check alone would leave a file-existence oracle and would not cover a database written before that check existed. A rejected segment is the ordinary 404, never a distinguishable error.
- Uploader identity defaults by evidence, not convenience: a proxy identity header (`X-Authentik-Username` or `X-Forwarded-User`) means a person, its absence means an agent. Mislabelling a person as an agent answers the owner's own question for him, which is worse than leaving a card open — keep the default on the agent side.
- `_thread_action` is a factory over store functions and forwards only a fixed key whitelist from the body (value, note, reason, actor, force, wake_at variants, hours, blocked_on, recheck_days, plus normalized attachments). A new store keyword is invisible over HTTP until its name is added to that list.
- The four-test self-check route is read-only and answers 200 whether the four tests pass or not — the verdict is data, never an error. It recovers `failed_test` by splitting the store's refusal on the first two colons, so the store message must stay in the shape `<prefix>: <test-name>: <fix>`.
- The email digest and the dispatcher heartbeat are file-backed on purpose: the heartbeat must remain readable by a cross-host watchdog when the store or its host is the thing that failed, so neither path opens the database. Both write a sibling temporary file then `os.replace`. The digest is also cached in a module global loaded at import, its path is `HELM_EMAIL_DIGEST` or a file beside the database, a GET before any push is 404, and the response flattens the pushed digest and adds `ts` and `age_s`.
- `/settings` interpolates stored label names, descriptions and prompt templates into HTML without escaping. It is authenticated and read-only; do not widen it to public access, and do not add further stored text to it, without escaping first.
- Configuration is read at import, never per request: `HELM_APP_TOKEN`, `HELM_DB`, `HELM_ATTACH_DIR`, `HELM_EMAIL_DIGEST`, `HELM_DISPATCHER_HB_FILE`, `HELM_CLAIM_LEASE_S`. Tests must set them before importing the module, and the module is imported as `app.service` (the container image copies this directory to `app/` beside the store package) — not as a submodule of the store package.
- `app = build_app()` runs at import and resolves route handlers by name then, which is why `metrics_route` may be defined after `build_app`. A handler renamed or removed without updating the route table fails at import, not at first request.
