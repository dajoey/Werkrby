# Harness Adapter DOX

## Purpose

- Own the provider-neutral harness interface, catalog/factories, transactional supervisor, and Codex, Claude Code, Agent Zero CLI, Pi, and ACP process adapters.

## Local Contracts

- Keep application and orchestration code harness-neutral; adapters map native events into the common response and follow-up contract.
- Codex maps strictly boolean `error.willRetry: true` to nonterminal `reconnecting` status, retaining diagnostics in captured events. Only nonempty agent-message, reasoning, or plan deltas for the exact active turn restore `running`; tool output and generic activity do not establish upstream recovery. Missing/false/malformed retry flags remain errors. Serialize admission, deferred replay, live notifications, and transport failure through callback publication; publish admission first and reject another turn's late events. Transport failure also fences pending admission so a successful RPC reply cannot resurrect an exited provider.
- Resume Codex threads with `excludeTurns: true`: Codex retains its conversation context, while Werkrby consumes only thread identity and its own bounded history. Any resume failure preserves the saved session and rejects dispatch instead of silently creating a replacement conversation. Keep the shared 16 MiB message bound; overflow and EOF close provider stdin as well as cancelling the subprocess so npm-launched native children receive EOF, fail pending/active work, and remain visibly unavailable through the supervisor until explicit restart or successful reconfiguration. Overflow diagnostics inspect only a bounded envelope prefix to identify a known notification or the correlated pending RPC, report unavailable metadata explicitly, and name the message-size limit and reconnect action without exposing payloads, provider IDs, arbitrary method strings, or replaying interrupted requests.
- Declare native-steer versus queued follow-up behavior explicitly, fence active executions, and invoke durable iteration reservation exactly once immediately before accepted provider delivery.
- Expose the provider-neutral new/steered/queued conversation admission classification at the same session fence so application correlation can cover consolidated terminal responses exactly.
- When an ordinary queued follow-up replaces an emitter, deliver its predecessor's continuing result followed by an explicit done-status release. This closes every request and balances application/channel activity without claiming logical completion. Orchestrator controls that preserve their emitter do not release it.
- An interruption attempt cancels not-yet-dispatched ordinary follow-ups with a terminal error per request, including every emitter in a dequeued batch. Capture the cancellation generation when removing queued work, preserve it through batching, and reject stale dispatch even if a successor turn is active. Queued controls retain their shared emitter; only the provider owns that execution's terminal event. Failure to interrupt the active provider does not restore already-cancelled queued requests. An interrupt never queues behind the active turn it is meant to stop: turns hold the per-key operation lock for their whole duration, so a busy lock means the turn itself is the holder and the interrupt proceeds under the supervisor state lock alone (target interrupts are safe against a live turn), covering the admission-to-registration window with a bounded wait; only with no turn running does it hold the operation lock across cleanup so a successor send stays fenced behind it.
- Order forward-looking model commits and dispatch snapshots under one supervisor fence. Never mutate an already-admitted provider turn; native steering remains part of that turn, while queued continuations and later top-level turns snapshot the newest model at their own provider-dispatch admission. A per-send model override (`SendWithModel`) stays with its turn: a queued send carries its own override, and controls and continuations reuse the override their job was dispatched with; only the model is pinned, the other inference properties still snapshot newest.
- Extend that fence to reasoning effort and service mode. Catalog metadata declares effort support for Codex, Claude, and Pi. Their model and effort values pass through to the provider without requiring discovery or catalog membership; validate bounded effort syntax at the shared boundary and let provider errors report unsupported manual choices. Codex reads per-model effort/service tiers for detected choices and passes `effort`/`serviceTier`; service selections still require verified capabilities. Claude passes `--effort`. Pi identifies its current/default model and current thinking level from `get_state`, queries each catalog model's exact RPC thinking levels in a separate no-session process selected by the non-persistent `--model` runtime override, labels a default effort only for the authoritative current model, and passes `--thinking`; never use Pi's persistent `set_model` RPC for capability inspection. Both legacy omitted and explicit Pi efforts reach the provider for validation/clamping. ACP model selection remains supported, but reasoning and speed are unsupported because ACP advertises optional thought choices only after session creation and defines no standard speed category.
- Herdr routes orchestrator work to a dedicated named worker per session key and closes that worker's tab after the turn. A later turn on the same key reuses the same registered worker, so the deferred close is owned by whichever turn ends last: it never runs while a turn is active for that key or while that key's send lock is held, and it leaves the worker registration intact in both cases. Forced teardown from an interrupt request bypasses the active turn check to close the worker pane and clear registration immediately even if the turn has not yet unwound. The herdr server is shared by every Werkrby workspace on the host, so the startup orphan sweep closes only worker-named agents whose cwd is this workspace's root; an agent with another or no cwd belongs to a live serve and is never swept.
- An empty or `default` Herdr model starts the `hermes` runner (the catalog default), and every other bare runner name is refused at launch, a retired one (agy, kimi, opencode, pi, claude) or any other kind herdr supports (codex, cursor and so on): only a roster staff entry may name another runner. A direct pane address (`w8:p2`) launches nothing and passes through. A hermes launch whose args carry no `-p`, `--profile` or `--profile=` gets the session key's worker profile in front (`wk-chat` for chat turns, `wk-notify` for notification and heartbeat turns, `wk-code` otherwise), so it never runs the root profile; args that name a profile are launched unchanged. One function (`herdrLaunch`) yields the launched kind and args and the ledger reader's args, so both name the same profile.
- A Hermes turn runs inside the root Hermes gateway, so herdr reports no session for it and it writes no transcript; it is judged from the launch profile's ledger (`-p`/`--profile` name, else the sticky `active_profile`, else the root: `<HERMES_HOME or ~/.hermes>[/profiles/<name>]/state.db`), opened `mode=ro` so the gateway's WAL is read and never `immutable=1`. Delivery proof is a user row written at or after the prompt was sent whose whitespace-folded text contains the whole prompt (never a head: task and chat prompts share their opening and closing text), taking the newest such row and following a session that ended by compression into its child; with that proof the prompt is never re-sent. The reply is the turn's last assistant row with text, no tool calls, no stop-gate continuation (`verify_hook_continue`, `verification_required`, `kanban_terminal_required`: a gated draft is superseded by its rewrite), skipping compaction summaries and display-only rows. A `failed_turn` boundary row returns `runner turn failed: <display_metadata error> [<error_surface code>]`, and a turn that wrote assistant rows but no answer after a short settle re-read is a turn error, never a reply. When the ledger cannot be read or holds no row for the prompt, the screen decides: the reply is the last complete reply box (a 40-wide turn rule after that box means the newest turn drew no box, so only that turn's text, without its `● ` prompt preview, is cleaned and an earlier turn's reply is never served), a newest turn ending in the corner-less `─ ☤ Hermes` panel is a turn error, and a reply box or panel on screen proves delivery. Harness tests point `HERMES_HOME` at an empty temp home in `TestMain` and never read the host's ledgers.
- A Hermes worker pane that herdr reports `blocked` (a prompt on screen, which the prompt watcher clears) is waited on, not failed: a submission herdr rejects with `agent_blocked` before any input is sent is submitted again once the pane clears, and a pane that blocks mid-turn is re-read until it leaves `blocked`, each within a five-minute bound (from the first rejection for the submission, per blocked episode mid-turn). A pane still blocked at the bound ends the turn with one error carrying `HermesBlockedCode` (`hermes_blocked`). Every other runner keeps the immediate `agent_blocked` error. A resubmission is typed only into a pane whose idle reading holds, never into one herdr reports `working`: a pane that clears into `working` resumed the turn it was blocked in, and a Hermes worker queues input typed into a busy pane and runs it as a second turn, so that turn is followed to its end first (its time moves the bound out). Before typing, the claimed document the dispatch names in the send's context (`WithClaimedDocument` / `ClaimedDocument`) must still be at its path; when the earlier turn moved it, nothing is typed and the turn ends with that earlier turn's ledger answer (when this process sent its prompt) or a note that the prompt was not sent, never with an error.
- The supervisor exposes three control primitives above the adapters: `SendControl` (queue-or-steer by the adapter's declared follow-up mode), `SendLiveControl` (deliver now: steer-capable adapters take their native steer path; queue-mode adapters implementing `LivePrompter` — herdr's `PromptLive` submits into the live worker pane without waiting — bypass the queue; anything else reports no live path instead of deferring), and `CancelQueuedControl` (withdraw a queued control before turn-end delivery; already-delivered or unknown ids report false without synthesizing provider or job events).
- `WithRunBoundary` alone activates the finite Hermes path; without it every legacy Herdr behavior stays unchanged. The path admits only configured headless Hermes staff with an explicit `wk-finite-test` or `wk-finite-wall` profile and a matching marker in a non-default disposable `HERMES_HOME`, never a pane or default profile. It uses a fresh `finite:<run-id>` session, no resume, no legacy roster assignment/usage accounting, no cap/repair or Agent Wall activity, and no orphan/idle sweeps. Run-private `hermes-provider.json`, `hermes-usage.json`, normalized `usage.json`, and any wall record bind the exact run ID and process token. Discover one exact full-prompt admission and persist its session/request/admission IDs, generation, and owner epoch; duplicates, missing identities, unreadable ledgers, `unknown` admissions/workers, and mismatches never prove absence. Client exit is nonterminal: return success only after the exact admission is terminal with no linked pending admission or live worker. Stop uses exact `prompt.cancel` plus generation-fenced `session.interrupt`, then reproves absence. The finite live-test supervisor supplies this context and combines OS and Hermes liveness/stop hooks; production defaults remain inert. Live tests use real client/gateway only after controlled gates pass, fetch credentials through the runtime secret bridge, and retain only non-secret disposable evidence.
- Build commands without shell interpolation, bound scanner/event payloads, surface startup and negotiation diagnostics, and keep portable fixture providers synthetic.
- Launch Pi RPC with `--mode rpc` plus only Werkrby's own session, model, thinking, and sandbox arguments so the user's ordinary global extensions, skills, prompt templates, themes, context files, and model/provider settings load; never pass resource-suppression flags or an approval override, and leave project-local resource loading to Pi's own non-interactive trust decision. Pi user/global resources belong to the user's Pi installation and remain separate from Werkrby's explicitly installed executable hooks. Because a trusted extension set can request interactive UI, answer blocking `extension_ui_request` dialogs (`confirm`, `select`, `input`, `editor`) with an immediate explicit cancellation and one provider-neutral status event, never respond to fire-and-forget methods, and keep the response write under the existing stdin mutex so no dialog can stall a headless turn.
- Claude Code establishes its session only from a literal `system`/`init` event carrying `session_id`; other `system`-typed events (for example SessionStart hook lifecycle events, which may carry the same `session_id` ahead of `init`) are tolerated and otherwise ignored while waiting for it. Only reject the stream as incompatible once a turn concludes (its `result` arrives, or the process/stream ends) without ever having seen literal `init`; do not abort on the first non-`system` byte, since ordinary hook or partial-message interleaving must not abort a turn that later establishes its session correctly.
- Keep Agent Zero CLI as the fixed `agent-zero` profile backed by the shared ACP adapter, launch `a0 acp`, and require a bounded successful `a0 acp --check` before reporting it available.
