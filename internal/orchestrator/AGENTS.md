# Markdown Orchestrator DOX

## Purpose

- Own durable task/goal workflows, claims and leases, recovery, review policy, semantic heartbeat, direct notification-agent dispatch, and ordinary delivery reconciliation.

## Local Contracts

- Treat Markdown as source of truth, claim queued phases atomically, fence provider work with phase-specific leases, preserve task-goal round links, and enforce configured transitions and review overlays.
- Recovery dispatch retires any ended local execution handle and resets the previous execution state and error before admission, preserving the public job number and archived history. Ignore events for retired handles. `recovering` covers restart preparation only: structured provider running evidence or successful admission returns the lease to `processing`, retaining the recovery count and journal. Serialize admission updates with provider events so terminal `awaiting_transition` cannot be overwritten; provider completion still requires durable transition reconciliation and never changes task/goal status by itself.
- Obtain agent-authored timestamps from the current environment clock; waiting requires a concrete external condition, and recovery may not bypass live ownership or required review.
- For every task `done`, `failed`, and `cancelled` transition and every actionable unscheduled `waiting`, directly start one ordinary asynchronous notification-agent job. Re-read and validate enabled notification metadata plus the selected outcome before prompt construction. Supply task evidence exactly once: preserve a safely fitting document in full, otherwise use a deterministic valid-UTF-8 beginning/recent-end JSON projection with an explicit untrusted middle-omission marker, omitted-byte count, and exact JSON-encoded absolute path for inspecting the complete authoritative Markdown. Budget that projection only after rendering the customized template, framework guidance, scope discipline, and persistent notification instructions; retain a documented 4 KiB safety margin below the 128 KiB provider boundary, and reject oversized non-task sections precisely. Supply a shell-safe command with the absolute executable/workspace and exact task origin already filled in, using `--message \"Hello there\"`; direct the agent to change only that message. At render time, omit obsolete delivery paragraphs from preserved workspace overrides while retaining their unrelated custom decision and writing guidance. The agent alone decides and edits task progress with its send, skip, or CLI failure; do not parse provider output or create notification-specific persistence, claims, bindings, results, recovery, or replay. Do not bind semantic-heartbeat guidance to a task origin.
- Admit manual semantic heartbeats through the same scheduler loop and provider fence as timer ticks; provider release after either mode owns the next fixed-delay deadline. The elected primary alone invokes the shared cleanup callback on an eight-hour cadence using the live retention value.
- Heartbeat reminder policy belongs entirely to the agent: it inspects bounded waiting-task progress, judges inactivity and usefulness, invokes the ordinary recent-authorized notification CLI, and journals a send/skip/failure in that task. The manager only triggers the heartbeat and injects this rule; it must not implement reminder queues, timers, thresholds, eligibility, identity links, correlation, acknowledgement, deduplication, contingency branches, or delivery orchestration beyond the ordinary notify primitive. At render time, omit retired read-only, original-origin-only, and action/JSON-result paragraphs from preserved workspace heartbeat overrides while retaining unrelated customized inspection and repair guidance.
- Treat heartbeat harness dispatch as worker admission, not a result protocol. Keep the provider fence through terminal release, ignore every provider payload, and persist no framework heartbeat action, finding, health, incident, escalation, retry, or notification state. The agent uses ordinary Werkrby CLI inspection and applicable Markdown workflow contracts to make the smallest evidence-backed repair, journals each durable change itself, and may request the existing serialized orchestrator trigger. Task terminal and actionable unscheduled waiting transitions dispatch their notification agent directly.
- Enforce the opt-in acceptance gate at task implementation hand-off (review or direct done). A front-matter `acceptance` block (`command`, `sha256`, `timeout_seconds`, `max_rounds`) arms a check that must also be the task's latest registration in the append-only acceptance registry (path from `SPYJO_ACCEPTANCE_REGISTRY`, default `~/ops/logs/acceptance-gate/registry.jsonl`; one JSON line per registration with `task` or `task_id`, a UTC time, and `sha256` — the shape the authoring tool writes). `command` names the check script by absolute path, optionally behind an interpreter (the authoring tool pastes `bash <path>`); the pinned sha256 always describes the script file itself. Werkrby re-hashes the script before running it and compares both records; a content mismatch, an unregistered or malformed check, or a registered task whose block was stripped is tampering: the hand-off is refused (`ACCEPTANCE CHECK TAMPERED`), never runs, and never counts a round. A failing exit bounces the hand-off back to `todo/` with the last 20 lines (capped at 700 characters) of combined output in Progress, records `acceptance_rounds`, and spends the attempt on the next claim (no resume credit). At `max_rounds` (default 2, cap 5) the still-failing task proceeds to the independent reviewer with every round's output in Progress for a check-or-work verdict; a direct completion is redirected to review unless review is globally disabled. Exit 0 passes. A check that is missing, not executable, cannot start, or times out (`timeout_seconds`, default 120, cap 600; the deadline's kill error is the timeout, not a failing exit), and an unreadable registry, are infrastructure failures of the gate itself: a loud Progress note, no round, no attempt, and the hand-off proceeds unchanged, so gate plumbing can never stall the board. A cancelled manager context mid-check writes nothing and spends nothing; recovery re-runs the transition. A task with no `acceptance` block and no registry entry hands off exactly as before the gate existed.
- Require application job admission before dispatching task, review, goal, heartbeat, or notification-agent provider work; an admission failure stops that dispatch and follows the owning workflow's ordinary error path. Forward admitted provider-neutral streams to the application job recorder without parsing their text. Archive capture never changes lease, transition, notification, or recovery decisions.
- A harness send error whose control-plane text is a provider refusing work right now (backend overload, "please retry") is retried exactly once in place on the same lease, before the ordinary error path, so a transient refusal costs neither a re-claim nor an escalation rung. Quota refusals, dead-runner signals, a cancelled context, and any error after the turn produced its terminal final response never retry in place and follow the ordinary failover path; the harness's own terminal error emitted immediately beside the refusal does not veto the retry, and the lease it parked in `awaiting_transition` returns to live-work state without that error before the second dispatch. Only the returned harness error text is matched; provider event streams are never parsed.
- A dispatch/execution error caused by the orchestrator's own lifecycle — the manager's context cancelled on shutdown, or a worker `signal: terminated`/`signal: killed` inside the short post-start settling window — is recorded as a restart interrupt, not a consecutive dispatch failure. It parks the lease in `error` for ordinary re-adoption, writes an "interrupted by a service restart … attempt not spent" progress line, and must not increment `RecoveryCount`, phase attempt, or move the document to `failed/`. Drain-on-shutdown is not used: re-adoption preserves the claim and delaying a restart for in-flight turns is what operators force-kill around.
- A task's `attempt` is spent only by work that failed or came back incomplete; it drives the roster escalation ladder and the fleet attempt cap. When Werkrby reconciles a task turn that parked the document in `waiting/` (implementation or review phase), it writes `resume_credit: true`; a routine review (lease `review_risk: routine`, recorded at the review claim) that returns the task to `todo/` after raising it to `risk: high` gets the same mark, since that hand-off to the risk-high reviewer is not rework; a direct completion rejected only on `completion_summary` format gets it once per attempt (`format_credit_attempt` records the attempt that used it; missing summary content still spends the attempt). Every claim removes the mark, and a task implementation claim that finds it on an attempt of at least 1 continues that attempt and journals "… attempt not spent", at most 5 times per attempt (`resume_credits_attempt`/`resume_credits_used` count them, parks and format-only repairs alike); the sixth spends the attempt and journals why, so a task that keeps re-parking still reaches the ladder and the cap. Every other reconciled task transition strips the mark, so a turn cannot credit its own requeue, and a park made outside a turn (the fleet attempt cap parks straight out of `todo/`) is never marked. Resume paths out of `waiting/` — the scheduled wake and external scripts — only have to preserve the field. Goal `planning_attempt`/`review_attempt` are not credited: they feed neither the ladder nor the cap, and a goal can resume into a different phase than the one that parked.
- Run heartbeat and notification agents through the same ordinary provider-neutral job lifecycle: `Send` admits asynchronous work and never implies completion, `Codex turn started` is nonterminal, and the first non-continuing final/error event, cancellation, or bounded timeout ends job ownership exactly once. Keep the complete accepted event stream through that boundary, ignore late/duplicate terminal events, and retain heartbeat cadence/non-overlap as a separate scheduling fence until provider release.
- Serialize terminal-task retention with goal scanning. Keep every settled task linked to any nonterminal goal in the live status folders until that goal reaches a terminal outcome; an incomplete nonterminal-goal index must fail safe by protecting goal-linked tasks.
- Own exactly two fixed workflows under `.spynel/tasks` and `.spynel/goals`, with fixed prompt paths, transitions, and 30-minute/task and two-hour/goal stale thresholds. Those thresholds size a turn that is still running; a lease left in `awaiting_transition` with its document still at its claimed path has a turn that already ended without moving anything, so recover it on a short bounded threshold instead, and hand it back to the ordinary threshold once its recovery turns have ended empty repeatedly. Do not persist route definitions in configuration, leases, or goal front matter. Task/goal creation prompts, scans, recovery, retention, status, and linked rounds share these canonical folders. Apply scanner interval changes by synchronously resetting the production timer and fence already-selected stale timer generations through the scan lock.
- `SettleTaskByOperator` is the operator-control twin of the honored review cancel: it moves a claimed task document to a terminal folder with the operator-authority note and (for done settles) the caller's checker-accepted completion summary, requests an immediate scan, and leaves stopping the run to the caller. The ordinary reconcile then owns validation, terminal hooks, and the notification decision exactly as if the worker had moved it.
